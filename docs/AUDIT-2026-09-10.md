## 3. Bugs found (ranked)

### P0 — Desktop chat cold-start renders an empty conversation
`seedTurnForConversation()` (`Chat.tsx:72`) is dead code — defined, never called. Opening `#/desktop/chat/consumer` from the sidebar, a deep link, or a refresh shows an empty column with only the composer; the rail still shows the Demand Notice. The seeded conversation has legacy messages (`ConversationContext.tsx:101`) but rendering is hybrid-turns-only (`Chat.tsx:489`), so nothing draws. The golden path works only if you type a fresh question. This breaks the app's single most important screenshot: the recruiter who clicks "Consumer Guide" first sees nothing.
**Fix:** on mount (or in `renderedMessages`), seed `hybridTurns` with `seedTurnForConversation(convId, language)` when the conversation is the seeded one and hybridTurns is empty.

### P0 — Boundary conversation answers as the consumer scenario
`runPreparedInput` (`DemoContext.tsx:194`) routes by the **global** `scenarioId` (default `consumer`). Opening `#/desktop/chat/out-of-scope` and asking the cricket question returned the consumer clarify turn ("When did you buy the mixer?") — the anti-hallucination guardrail scenario demonstrates the wrong behavior. Same root cause as P0-1: the URL never calls `selectScenario`.
**Fix:** map `convId === 'out-of-scope'` → `selectScenario('out_of_scope')` in the Chat mount effect.

### P1 — Clarify turn offers no answer options on desktop
The clarify copy says "Pick the closest answer below" but desktop `Turn.tsx:551` renders only the three text zones — no option rows (mobile `MobileConsumerCase.tsx:420` has them). Users must guess that typing works. Also: typing a date **did not send on Enter** in the test (submit worked via the button); `submit()` bails silently when `canSend` is false, so if `runPreparedInput` is in-flight, Enter is a no-op with no feedback.

### P1 — Wordmark/logo tile invisible in dark mode
`LogoMark` (`shared.tsx:570`) hardcodes glyph `#F7F4ED` on tile `C.navy`. In dark theme `C.navy` re-points to a light navy and the glyph stays cream → the brand mark on mobile home/notice renders as a **blank cream rounded square** (confirmed on `/mobile/home` and `/mobile/notice`). First-touch brand moment, broken in the default (system dark) theme.

### P2 — Cross-shell identity inconsistency
Mobile drawer: "Priya S. · Karnataka", active matter "Outside LokAI Scope". Desktop sidebar: "Priya Sharma · Mumbai", active matter "Refund for a damaged mixer". Also the desktop boundary conversation shows the **consumer** Demand Notice rail. A recruiter watching both shells will read this as unfinished.

### P2 — Entrance animation reads as broken for ~2s
Dashboard and Case Files captured mid-entrance look washed-out (whole content at low opacity, long stagger). On slow machines/screenshots this reads as a render bug. Tighten total stagger duration to <1.2s.

### P3
- Boundary conversation seed (when fixed) must also fix the rail context.
- Specimen pages overflow horizontally at 390px (embed canvas wider than viewport).
- "2 of 3 claims sourced" header clips at 760px chat width on some states.
- Settings panel opens on `?` (observed open over chat after one navigation) — verify the trigger.

## 4. Design system — A-to-Z consistency verdict

**This is the strongest part of the project and it is genuinely rare at this level.**

- Four-layer law (tokens → primitives → layout kit → domain) is real, not aspirational: `verify-demo.mjs` fails the build on raw hex/font/size/radius/shadow outside the six system files, and a per-file **ratchet** (471→390) means drift can only fall.
- WCAG AA contrast is **machine-checked in both themes** — almost no student/portfolio project does this.
- Multilingual typography is a system property: `<Text role>` resolves family + leading per script (Fraunces/Hanken for Latin, Noto for Devanagari/Tamil), verified live in the Hindi/Marathi screens.
- Icons: one aliased set (`ui/icons.tsx`), Lucide/Phosphor fully retired (0 imports left). Vendor swap = one file.
- One-primary-button law, border-OR-shadow law, status vocabulary (`statusVocabulary.ts`) — all enforced or mechanical.
- The `/dev` catalog + self-labeling specimens is a differentiator: it proves the system composes, and doubles as case-study capture tooling.

Dents (all minor): `Turn.tsx` still carries 23 raw-family debt lines (worst file, by design — it defines its own zones); `CaptureLayout` 6; a handful of `ease'` defaults vs the canonical `cubic-bezier(0.22,1,0.36,1)`.

## 5. UX & motion

**Good:** hybrid response modes (clarify/explain/disclose/stop/confirm/recover) are a real product thesis, not decoration; the stop states (dark-native desktop column, luminous mobile inversion) are the best-designed refusals I've seen in a demo; tool sheets contained; attachment tray; skip/replay on progress; haptics on key moments; `prefers-reduced-motion` respected per primitive; `:focus-visible` global ring; one motion source (`ui/motion.tsx`).

**Gaps:** desktop clarify options (P1 above); silent no-op Enter (P1); entrance staggers too slow (P2); voice idle state under-art-directed (orb placeholder-like); no empty-state illustration language yet.

## 6. 2026 standards & recruiter competitiveness

**Verdict: this is "insanely well crafted" territory — top few percent of portfolio projects — not Dribbble-flash, and that is the right call for a legal-AI case study.** It matches what makes 2026 references (Wkeel, Gemini mobile, Claude/ChatGPT drawers) feel premium: editorial serif at display sizes, warm paper ground, hairline structure, contact shadows, tone inversion for stops, drawer-first mobile nav, live document canvas on the rail.

Against the bar:
- ✅ Typography-led hierarchy, real type scale, per-script families — **exceeds** typical portfolio work
- ✅ Motion: purposeful, reduced-motion-aware, one easing curve — **meets** the bar
- ✅ Dark theme as role re-point with contrast gate — **exceeds**
- ✅ Deterministic-demo honesty (no fake AI, no fabricated confidence, capped capability claims) — **exceeds**; recruiters notice guardrails
- ⚠️ First-impression paths (desktop cold chat, mobile brand mark) are the broken bits — **these are what a recruiter clicks first**, so they gate the grade
- ⚠️ 1.4 MB main chunk; code-split the lazy routes' shared vendor (recharts, radix, motion) — cheap win
- ❌ Nothing at "dribbble" gloss (3D, gradients, noise textures) — deliberately absent; do not add it, the editorial restraint *is* the differentiation

**Overall grade: A− and one fix-session away from A.** The P0s are both small, localized fixes (`Chat.tsx` seed + scenario routing) with outsized first-impression payoff.
