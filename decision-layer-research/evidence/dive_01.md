# Dimension 01: JEV mechanics (orchestrator-run; all 4 subagent dispatches failed on provider capacity)

Sources captured directly this run: typesafe.ai homepage (browser), flaviocopes.com/jev deep-dive (browser, updated Sep 21 2026), Ricker's two X articles (browser), Codila roadmap (browser), plus search snippets (langchain.com, mindstudio.ai, aihubmix). Vendor claims are marked as such.

## Current State (what Jev is and how it works)

- **Identity & launch:** Jev is TypeSafe AI's "first public System One model", announced Sept 15, 2026 after "two years in stealth" (typesafe.ai homepage, browser capture). Positioning: "System One Models are a new class of AI model built for decisions inside software"; tagline "The First (Public) System One Model; Jev Gives AI The Properties Of Code".
- **What it does NOT do (vendor's own framing):** "Jev is not a chatbot like ChatGPT, and it is not a coding model. It does not write replies, explanations, or code." (flaviocopes, browser capture). "Not Chat" appears literally on the vendor homepage.
- **Core contract:** "You send it data and a list of typed questions. It sends back one answer per question: a yes/no probability, one option [from a list, or] a [scale] position..." (flaviocopes). Homepage: "Decisions, Not Strings — Typed outputs that software can act on"; "LLMs produce words for people. Jev produces typed decisions and is more like code: reliable, fast, self-consistent" (browser capture).
- **The three question types (flaviocopes, verbatim schemas):**
  - **Noul** — yes/no with probability: request `{"refund_requested": {"type": "noul", "instructions": "Does the customer ask for money back?"}}` → response `{"refund_requested": {"type": "noul", "noul": 0.93}}`. Supports `criteria` per branch.
  - **Choice** — pick one option: `{"department": {"type": "choice", "instructions": "Which team should handle this message?", "criteria": {...}}}` → `{"department": {"type": "choice", "choice": "billing", "probabilities": {"billing": 0.84, "technical": 0.15, "sales": ...}}}`. Up to 255 options per Ricker's article.
  - **Score** — position on a described scale: `{"bug_severity": {"type": "score", "instructions": "How severe is the reported issue?", "criteria": [...]}}` → `{"bug_severity": {"type": "score", "score": 1.3, "confidence": 0.54, "legend": {"0": "Cosmetic; no impact on function..."}}}`.
- **State design:** "STATE: WHAT YOU GIVE JEV TO LOOK AT" — caller passes structured JSON (e.g., message, order with charges array, refund_policy) and questions reference fields backtick-style ("Does `refund_policy` cover the situation described in `message`?"). Ricker's guide: "Jev is only as good as the state you hand it. It does not go looking for context. It decides on exactly what you give it... Give it evidence, not vibes." (browser capture)
- **Agent loop:** Ricker: "state → decision → action → verification → next state"; "An LLM creates the work. Something else should decide what happens next." Chief-of-Staff dispatch pattern: workers receive jobs, results return to shared state, Jev picks next worker; "If decision.confidence >= 0.85: dispatcher.send(...)" (article code). Batch API: "three decisions, one round trip" — questions must not read one another's answers.
- **Harness (router + gate):** "The harness gives you two layers of Jev, and neither one generates text. The model router at the top picks the cheapest [model]; [the gate] checks every tool call before execution — blocks risky actions, approves safe ones." (Ricker article, browser capture)
- **Compaction:** "Context compaction has always been a summarization prompt... Jev makes it instant by scoring every entry and dropping what is irrelevant. It is not a summary pass. It is a relevance [filter]" (Ricker article).
- **API & SDKs:** `POST https://api.typesafe.ai/v1/systemone` (Bearer key); Node `npm install @typesafe-ai/sdk` (`choice, noul, score, TypeSafeClient`); Python `pip install typesafe-sdk` (`Choice, Noul, Score, TypeSafeClient`); Vercel AI SDK `@ai-sdk/typesafe-ai` via `experimental_evaluate`. Model ids: `jev-latest`, `jev-1.13.0`. Coding-agent skill: `npx skills add typesafe-ai/skills --skill typesafe-ai`; Claude plugin install supported. LangChain published an integration guide (langchain.com search snippet).
- **Calibration & determinism claims:** homepage FAQ headers include "Is Jev Deterministic?" and "Can Jev Still Get Things Wrong?"; "Zero Hallucinations — Every Jev decision comes with a confidence estimate, so your software can act when confidence is high and escalate when [low]"; "Calibrated Confidence — Every decision includes an estimate of how confident the model is"; training framing: "reinforcement learning for calibrated decisions" (RLVR/RLCD references on the research stack diagram). FAQ answers were collapsed (not captured) — the "Zero Hallucinations" headline is marketing shorthand for "decisions are typed and confidence-estimated", not a literal accuracy guarantee; flagged accordingly.
- **Cost/performance claims (all vendor-side):** homepage: "$42 Per Billion input tokens. 238x Lower input price than Claude Fable 5.1"; live demo pair: Jev "Cost $0.000081 Completed in 0.114s" vs GPT "Cost $0.013880 Completed in 8.566s" (~171x cheaper, ~75x faster in that demo; corrected by adversarial review — input-price only, output pricing uncaptured); blog headline: "We Took The Opposite Research Direction 193.6x Faster, 444.6x Cheaper" with asterisk "*Based On Workflows For System One Tasks (Proof)" — scope-limited to System One tasks. Ricker repeats "up to 193x faster and 444x cheaper in our tests". Ricker's article cites "$0.042/M input" (≈$42/B — consistent). **No independent benchmark found in this run** — searches surfaced only vendor + promoter + tutorial content.
- **Where it breaks (flaviocopes section "WHERE JEV BREAKS"):** example shows an odd-item list (`['typesafe','apple','california','banana','orange']`) queried per-item — pattern indicates weaknesses on (a) many-item fan-out beyond batch/option design limits and (b) decisions needing generative world knowledge rather than classification over provided state. Full body not captured; treat as "documented failure-mode section exists; details partial".
- **Ecosystem reception:** LangChain guide (search snippet), MindStudio/aihubmix explainers, flaviocopes deep dive; Codila frames it as "Jev is the 'Internet' moment for the AI industry... the AI engineer's stack for 2028" — promoter hyperbole, not evidence. No HN/Reddit independent benchmarking surfaced in this run's searches.

## Tensions & Counter-arguments

- **"Zero Hallucinations" headline vs FAQ honesty:** the same site asks "Can Jev Still Get Things Wrong?" — a decision model can still be *wrong*; "zero hallucinations" means no invented prose, not zero error. For legal use, miscalibrated confidence on a wrong classification is precisely the Mata-style failure in new clothing.
- **All economics are vendor-measured:** "in our tests" (Ricker), "*Based On Workflows For System One Tasks" (TypeSafe). No independent replication found this run. The 238x/444x numbers compare Jev decision-calls against full LLM calls — category difference, not apples-to-apples model comparison.
- **The real innovation may be the contract, not the model:** typed decisions + calibrated confidence + explicit state + act/escalate thresholds is an engineering discipline any team can adopt with structured outputs + a router + a guardrail classifier (see dive_02 prior art). Jev's edge is packaging and (claimed) latency economics.
- **State design is the new prompt engineering:** "It decides on exactly what you give it" cuts both ways — in legal triage, the state builder decides what the decider sees; an omitted adverse fact yields a confident wrong routing. LokAI already knows this: its verification gate makes the USER confirm facts precisely because facts drive the answer.
