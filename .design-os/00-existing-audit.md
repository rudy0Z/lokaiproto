# Diagnose

## Product and code context

LokAI is a React/Vite portfolio prototype for first-time legal encounters in India. The approved direction is a deterministic, fully scripted demonstration: no paid model calls, no browser microphone or file permissions, and no unsupported production claims. The focused story is one complete consumer-refund matter plus deliberate guardrail demonstrations for missing facts, source gaps, conflicting rules, high-risk escalation, out-of-scope requests, and recovery.

The current code mixes a live API/device prototype with static screen scripts. Desktop chat uses `ConversationContext` and service calls; mobile case progression uses `caseWorkflow`; mobile files use `matterIntelligence`; several pages maintain additional local matter and document arrays. Language state is similarly split.

## Preserve

- Warm navy, cream, saffron identity with Fraunces editorial headings, Inter UI copy, JetBrains Mono evidence labels, and appropriate Noto families for Indian scripts.
- The three-part answer hierarchy: what the law says, what it means for the user, and what the user can do next.
- Fact verification, evidence comparison, source inspection, source-gap states, high-risk escalation, intent preview, user-controlled drafting, review gates, and audit history.
- Mobile bottom navigation for compact screens and desktop sidebar navigation.
- The one fully developed consumer-refund journey and honest boundaries around unsupported matters.

## Findings

- Real NVIDIA/Sarvam, OCR, STT, TTS, microphone, audio, and file-input paths contradict the deterministic demo contract.
- Desktop and mobile consume different matter, language, source, document, and progression models.
- Static records are presented as verified retrieval; arbitrary grounding percentages imply precision without a derivation.
- Scripted tenancy content incorrectly attributes a 30-day deposit-return rule to Maharashtra Rent Control Act section 24. All legal copy requires official-source mapping and qualified review before publication.
- Mobile language chat screens duplicate response anatomy, timing, copy, and controls.
- Three visual token sources, missing Fraunces/Inter imports, hard-coded values, repeated side stripes, contrast failures, inert controls, and incomplete dialog semantics weaken consistency and accessibility.
- Desktop is a fixed minimum-width workspace and mobile is a fixed artboard. This is acceptable for portfolio scenes only when the viewport contract is explicit; tablet navigation should adapt to a rail.

## Re-entry phases

Re-enter phases 2, 3, 4, 5, 6, and 7.

- Phase 2: define one matter model, scenario registry, navigation contract, and explicit removals.
- Phase 3: preserve the visual identity while moving desktop from marketing-hero composition toward matter continuity.
- Phase 4: consolidate tokens, typography, surfaces, legal-term affordances, and component states.
- Phase 5: rewrite technical labels and errors in plain language; build an official-source glossary.
- Phase 6: specify deterministic waiting, guardrail, glossary, review, correction, and recovery interactions.
- Phase 7: implement the shared engine and refactor desktop/mobile presenters.

## Gate

PASS — The audit names the existing split, legal and accessibility risks, preservation constraints, the approved focused scope, and evidence-driven re-entry phases. Verification remains absolute and legal publication remains blocked pending qualified review.
